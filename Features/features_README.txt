CUSTOMER METRICS - DATA DICTIONARY

Generated by scripts/build_features.py from Data/ (about 2.5 min, stdlib Python only):
    python scripts/build_features.py

Files
  customer_monthly.csv   122,400 rows = 5,100 customers x 24 months (2024-10 ... 2026-09). Long format.
  customer_features.csv    5,100 rows = one per customer. 90 columns.
  Join key in both: customer_id (same as in Data/).

Conventions
  - All money in EUR. Spending columns are POSITIVE numbers (the raw data stores them as negatives).
  - "spend" = purchases + utilities + housing. Savings/investment moves are NOT spend.
  - "income" = salary + other_income + investment_withdrawal.
  - "savings" = investment_deposit + salary_sweep - investment_withdrawal.
  - Balances are end-of-day balances. Days without transactions carry the previous balance forward,
    so every calendar day from the account's first transaction to 2026-09-30 is counted.
  - Oct 2024 is a partial month for about half the customers (accounts start 1-23 Oct). Per-customer
    averages in customer_features.csv use only the 23 full months 2024-11 ... 2026-09.
    customer_monthly.csv keeps Oct 2024; use days_observed to filter or weight it.
  - Shares and ratios are 0-1 fractions (not %). Empty cell = not applicable (e.g. no mortgage).

=== customer_features.csv ===
Demographics

  n_full_months               full months used for averages (23 for everyone)
  n_tx                        all transactions, whole period
  tx_per_month                average transactions per full month

  purchase_hour_mean          average hour of day

  payday_spend_ratio          payday_spend_share / share expected if spending were uniform.

Merchants

Pre-application features (mortgage customers only) - USE THESE TO PREDICT THE DECISION
  The whole-period features above include months AFTER the decision, which leaks future
  information. The pre_app_* columns only use data from before the application.
  pre_app_window_months       full months before the application month (14-21)
  pre_app_income_monthly_mean, pre_app_spend_monthly_mean, pre_app_purchases_monthly_mean
  pre_app_spend_to_income, pre_app_savings_rate
  pre_app_balance_at_application   end-of-day balance the day before the application
  pre_app_balance_min              lowest balance before the application month
  pre_app_share_days_negative
  pre_app_n_large_purchases
  pre_app_income_to_required  pre_app_income_monthly_mean / required_monthly_income_eur


Notes for modelling
  - customer_monthly.csv is the natural input for a hierarchical model: months nested in
    customers, customers nested in postal_area / age groups.
  - Income is very close to required_monthly_income for almost every mortgage customer
    (pre_app_income_to_required ~ 1.0 for both outcomes), so it is a weak predictor on its own.
  - Mortgage customers save a lot more than average before applying (median pre_app_savings_rate
    ~0.8, against ~0 for all customers).
  - Only 50 rejections (34 for collateral), so outcome models have very little data to learn from.
